# PodStacker Console Constitution
**Landscape Mode**

This document defines how PodStacker behaves, feels, and structures itself in landscape orientation.

Landscape mode is not a separate UI. It is:

**The PodStacker dashboard unfolded into a listening machine.**

Same system. Higher density. More surfaces.

---

## Core identity

In landscape mode, PodStacker becomes:

**A personal podcast mission-control console.**

It should feel:
- powerful
- orchestrated
- feature-rich
- inspiring
- clearly purpose-built

Not a tablet layout. Not a stretched phone app. **A machine for listening, capturing, and organizing audio.**

---

## Relationship to portrait

- **Portrait mode** = compressed state
- **Landscape mode** = deployed state

Rotation should feel like:
- panels revealing
- surfaces unfolding
- depth increasing

Never:
- snapping to a new screen
- resetting context
- hiding playback

The user is **opening the same machine wider**.

---

## Center of gravity

The landscape console is built around:

1. **Now Playing** (always anchored, always visible)
2. **Your local system** (downloads, what's next)
3. **Your constructed archive** (stacks, pins)

The console shows:
- What is happening
- What I own
- What I've collected

---

## Core console layout

By default, the console centers on:

### 1. Now Playing module
- Top, central anchor
- Current episode
- Timeline & progress
- Pin access
- Core playback controls

**This never leaves.**

### 2. Main board (default: Downloads)
The central surface shows your local machine state:
- Downloaded episodes
- Queued items
- In-progress items
- What's next

This is not browsing. This is your **system dashboard**.

### 3. Mode tabs (global console controls)
Across the top:
- Library
- Search
- Downloads (default)
- Pins
- Wave (future listening/visual mode)

These are not screens. They are **machine modes**.

The console frame remains. The active surface changes.

---

## Pins and stacks

**Pins are not logs. They are objects.**
**Stacks are not lists. They are containers.**

### Stack behavior:
- Opening a stack pulls a **tray from the side**
- The dashboard remains running
- Playback is not replaced
- The tray docks beside the console

Stacks feel like **trays you slide out of the machine**, not pages you go to.

### Inside a tray:
Pins appear as:
- cards
- tiles
- visual, scannable, object-like

Not rows. Not timestamps. Not reports.

**Each pin is a collected artifact.**

---

## Motion language

Landscape motion should feel:
- orchestrated
- layered
- mechanical
- intentional
- calm but powerful

Examples of correct feelings:
- panels revealing
- trays sliding out
- surfaces separating
- depth increasing
- systems activating

Not:
- card flipping
- page sliding
- app switching

---

## The unfolding rule

Rotation into landscape should always preserve:
- what is playing
- what was active
- what trays were open

And only add:
- more space
- more modules
- more context

**The machine opens. Nothing resets.**

---

## Summary of console laws

1. Landscape is an unfolded state
2. Now Playing is always anchored
3. Downloads are the default board
4. Modes change surfaces, not the machine
5. Stacks are side trays
6. Pins are cards
7. Playback never leaves
8. The console always feels powered

---

This document defines the premium identity of PodStacker. If landscape mode ever feels like "a layout," the app has drifted.
